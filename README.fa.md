# حق‌سنج — نسخه بومی اندروید

> **آزمون API و منطق:** بررسی زنده با حساب مجاز و ایجاد داده آزمایشی انجام شد؛ ناسازگاری سندسازی، مهلت، نوع تحلیل، ساده‌سازی، صفحه‌بندی و منطق گفتگو/SSE اصلاح شد. نتیجه نهایی ۷۱ تست موفق، Lint بدون خطا و بدون ساخت APK است. گزارش و حدود باقی‌مانده: [آزمون API](docs/API-AUDIT.fa.md). گزارش ۵۰ تست رابط در ادامه مربوط به مرحله قبلی است.

> **به‌روزرسانی سورس رابط:** در مرحله جدید فقط سورس تغییر کرده و APK/ZIP جدید ساخته نشده است. طراحی سرمه‌ای/طلایی مطابق مرجع زنده سایت، ورود به‌عنوان نخستین صفحه و چیدمان موبایل/تبلت اضافه شده‌اند. گزارش جاری: [بازبینی رابط](docs/UI-REVIEW.fa.md). ۵۰ تست موفق، ۲ تست زنده عمداً اجرا نشده، Lint بدون خطا. توضیحات APK و ۴۰ تست در متن زیر مربوط به تحویل قبلی‌اند، نه این مرحله.

نسخه 2.0.0-native (کد ۳)، بسته `ir.hsai.mobile`، حداقل Android 10 (API 29)، هدف API 35.

این پروژه بازنویسی بومی Kotlin و Jetpack Compose است؛ رابط، ناوبری، فرم‌ها و صفحه‌ها WebView یا HTML نیستند. API موجود `https://hsai.ir/api/v1` مصرف می‌شود و سایت/سرور اصلی تغییر نکرده است. پوسته فارسی راست‌به‌چپ، فونت وزیرمتن، کارت‌های یکدست با مرجع سایت و حالت روشن/تیره دارد.

## امکانات پیاده‌سازی‌شده

- گفت‌وگوی حقوقی و دریافت پاسخ جریانی، بازخورد و تاریخچه گفتگو
- حساب کاربری، ورود/ثبت‌نام، OTP وابسته به تنظیمات واقعی سرور، تغییر مشخصات/رمز
- ۱۰ محاسبه‌گر حقوقی با قراردادهای API رسمی
- تحلیل لایحه، برگه قضایی، انتخاب تصویر/دوربین و پوشاندن محلی اطلاعات تصویر پیش از ارسال
- اسناد، مشاهده/ویرایش/حذف و دریافت خروجی؛ جستجوی قوانین
- مهلت‌ها و یادآور محلی، پشتیبانی، طرح‌ها و آغاز جریان پرداخت
- نگهداری رمزگذاری‌شده نشست با Android Keystore؛ هیچ نام کاربری، رمز ادمین یا کلید خصوصی در سورس تحویلی قرار ندارد

وجود پیاده‌سازی به معنی تأیید نهایی تمام مسیرها روی گوشی واقعی نیست؛ محدودیت‌های آزمون در ادامه آمده است.

## ساخت

نیازمندی‌ها: JDK 17، Android SDK Platform 35 و Build Tools 35.0.0، اینترنت برای دریافت وابستگی‌ها. پروژه را در Android Studio باز کنید و مسیر SDK را در `local.properties` محلی تنظیم کنید، یا `ANDROID_HOME` را به SDK اشاره دهید.

```sh
chmod +x gradlew
./gradlew --no-daemon assembleDebug
```

خروجی: `app/build/outputs/apk/debug/app-debug.apk`.

APK تحویلی **Debug** است؛ برای انتشار عمومی باید با کلید اختصاصی مالک، نسخه Release ساخته و امضا شود. کلید Debug این محیط عمداً در سورس نیست؛ بازسازی Debug روی دستگاه دیگر امضای متفاوتی خواهد داشت و ممکن است روی نصب قبلی به‌صورت به‌روزرسانی نصب نشود. APK تحویلی با گواهی نسخه قبلی پروژه هم‌امضا است؛ ورود کاربر در بازنویسی بومی به‌صورت خودکار از نسخه وبی مهاجرت نمی‌کند.

## آزمون‌ها

برای محیط کم‌حافظه ابتدا تست‌ها را کامپایل و سپس در فرایند جدا اجرا کنید:

```sh
./gradlew --no-daemon compileDebugUnitTestKotlin
./gradlew --no-daemon -Dorg.gradle.jvmargs='-Xmx384m -XX:MaxMetaspaceSize=256m -Dfile.encoding=UTF-8' testDebugUnitTest
./gradlew --no-daemon lintDebug
```

دو تست زنده به‌طور پیش‌فرض اجرا نمی‌شوند؛ اجرای اختیاری آن‌ها به سرور تولید درخواست خواندن عمومی و POST محاسبه می‌فرستد، نه تغییر حساب یا پرداخت:

```sh
HSAI_LIVE_TESTS=1 ./gradlew --no-daemon -Dorg.gradle.jvmargs='-Xmx384m -XX:MaxMetaspaceSize=256m -Dfile.encoding=UTF-8' testDebugUnitTest --rerun-tasks
```

در محیط محدود، اجرای مجدد همه وظایف ممکن است RAM بیشتری بخواهد؛ بهتر است پس از کامپایل، فقط خروجی تست قبلی را پاک و فرمان تست را اجرا کنید.

آخرین اجرای تحویلی: **۴۰ تست موفق، صفر شکست/خطا/نادیده‌گرفته‌شده**؛ ۳۲ تست منطق/قرارداد شبکه، ۶ تست رابط Compose با Robolectric و ۲ تست زنده شامل چهار endpoint عمومی و هر ده محاسبه‌گر. Lint: صفر خطا، شش هشدار مربوط به نسخه‌های جدیدتر کتابخانه‌ها. شواهد خام در `verification/` است.

## محدودیت‌های صریح تحویل

- تست رابط با Robolectric API 29 و رندر بومی انجام شده است؛ تصاویر `screenshots/` اسکرین‌شات دستگاه یا شبیه‌ساز بوت‌شده نیستند. شبیه‌ساز کامل به علت کمبود RAM محیط راه‌اندازی نشد.
- نصب و گردش کامل روی گوشی، دوربین و جهت EXIF عکس، دسترسی فایل و دانلود، حفظ نشست پس از مرگ فرایند، اعلان‌ها و زمان‌بندی یادآور، بازگشت از درگاه پرداخت باید روی دستگاه واقعی آزموده شوند.
- ورود زنده احراز هویت‌شده، چت/SSE، OCR، ثبت/ویرایش/حذف داده خصوصی، پیامک و پرداخت واقعی در این بازنویسی انتهابه‌انتها اجرا نشده‌اند. تست‌های mock و عمومی جایگزین این آزمون‌ها نیستند.
- بازگشت پرداخت به معنی موفقیت قطعی پرداخت نیست؛ وضعیت باید از API سرور دریافت شود. فعال بودن OTP تابع تنظیمات سرور است.
- این یک نسخه قابل نصب برای ارزیابی است، نه ادعای آمادگی انتشار عمومی یا صحت مشاوره حقوقی.
