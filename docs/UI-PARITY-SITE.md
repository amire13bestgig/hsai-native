# برابری ظاهری اپ با سایت حق‌سنج

نسخه: `2.0.1-native` (کد ۴) — بازطراحی لایهٔ بصری بر پایهٔ `tailwind.config.js` و `src/index.css` سایت.

---

## ۱) معنی «دقیقاً مثل سایت» در یک اپ بومی

سایت یک برنامهٔ وب با Tailwind است؛ اپ بومی نه DOM دارد، نه `backdrop-filter`، نه `clamp()`.
بنابراین برابری در سه لایه معنا پیدا می‌کند و هر سه پیاده شده‌اند:

| لایه | چه چیزی منتقل شد | شاهد |
|---|---|---|
| **توکن‌ها** | پالت navy/brass (۲۱ رنگ)، سطوح `--soft-*` روشن/تیره، گردی‌ها، نسبت خط‌ها | `verify/tokens.py` → **۳۹/۳۹** |
| **کامپوننت‌ها** | کارت خمیری، حباب چت، نوار بالا، جعبهٔ ورودی، دکمهٔ اصلی، چیپ/تب، برگهٔ کاغذی قضایی | `docs` همین فایل + `SiteDesign.kt` |
| **چیدمان** | عرض محتوا ۱۱۵۲dp (max-w-6xl)، شکست ۱۰۲۴dp، سربرگ گرادیانی، ریل/سایدبار سرمه‌ای | `Page`/`workspaceLayout` |

آنچه **عمداً** یک‌به‌یک کپی نشد: صفحات بازاریابی وب (لندینگ، فوتر لینک‌ها، مودال‌های وب) که در اپ بومی کارکرد ندارند.

## ۴) بازبینی‌های قابل تکرار

```bash
python3 verify/tokens.py      # ۳۹/۳۹ برابری توکن با سایت
bash    verify/run.sh         # ۲۶/۲۶ قرارداد کلاینت
bash    verify/typecheck.sh   # ۰ خطای نوع روی کل ماژول + صحت امضای APIها
```

`typecheck.sh` با `android.jar` (Platform 35) + Compose 1.7.6 + Material3 1.3.1 نوع‌های کل
`app/src/main` را حل می‌کند. تنها چیزی که در این محیط قابل تأیید نیست، **کدبایت نهایی** است
(نیازمند پلاگین کامپایلر Compose و AAPT در Gradle): `./gradlew assembleDebug` روی ماشین دارای SDK.

## ۵) محدودیت‌های صادقانه

- تفاوت‌های ریز رندر فونت (hinting اندروید در برابر مرورگر) با برابری توکن‌ها حل نمی‌شود.
- `backdrop-filter` مرورگر در Compose معادل ندارد؛ شیشه با شفافیت لایه‌ای شبیه‌سازی شده و متن
  هرگز تار نمی‌شود (خوانایی مقدم بر تقلید است).
- سایه‌های چندلایهٔ CSS (`inset` + بیرونی) به `shadowElevation` ساده‌سازی شده‌اند.
- انیمیشن‌های وب (`aurora-slow`, `float-slow`, `shimmer`) عمداً به اپ منتقل نشدند: روی موبایل
  خود سایت هم زیر ۷۶۸px خاموش می‌شوند.

## ۶) وضعیت دقیق برابری، صفحه‌به‌صفحه (بدون ادعای اضافی)

### برابر شده و ماشین‌بازبینی شده ✅
پالت (۲۱ رنگ)، سطوح `--soft-*`، گردی‌ها، نسبت خط‌ها، کارت خمیری، حباب چت، ورودی چاهی،
دکمهٔ اصلی/ثانویه/برنجی، چیپ‌های تب و پیشنهاد، مودال (`.soft-modal`)، برگهٔ کاغذی قضایی،
نوار بالای می‌کلای، آیکون‌های گرد نوار بالا، سربرگ گرادیانی، تب‌های قرصی، نوار وضعیت، پوستهٔ تیره.

شاهد: `tokens.py` ۳۹/۳۹ · `typecheck.sh` ۰ خطای نوع · `run.sh` ۲۶/۲۶.

### هم‌زبان ولی نه پیکسل‌به‌پیکسل ⚠️
- **سایه‌ها**: CSS چندلایه (`inset` + بیرونی) در Compose به یک `shadowElevation` ساده‌سازی شده.
- **شیشه**: `backdrop-filter` در بومی معادل ندارد؛ با شفافیت لایه‌ای شبیه‌سازی شده و متن تار نمی‌شود.
- **فونت**: hinting و متریک اندروید با مرورگر تفاوت ریز دارد (همان فایل Vazirmatn).
- **انیمیشن**: `aurora/float/shimmer` منتقل نشد؛ خود سایت هم زیر ۷۶۸px خاموش می‌کند.
- **TextButton‌ها**: دکمهٔ شبح سایت، بدون پس‌زمینه است؛ تفاوت شکل (قرص M3) دیده نمی‌شود.

### عمداً منتقل نشده ❌
- صفحات بازاریابی وب (LandingPage، فوتر لینک‌ها، مودال‌های وب، Command Palette) که در اپ بومی کارکرد ندارند.
- پوستهٔ دو ستونی وب در حساب/پرداخت؛ اپ همان اطلاعات را در صفحهٔ بومی نشان می‌دهد.

### تأییدنشده (محدودیت محیط) ⚠️
- رندر واقعی روی دستگاه/امولاتور: APK در این محیط ساخته نمی‌شود (AAPT + پلاگین Compose لازم است).
- رفتار لمسی/اسکرول/RTL در دستگاه واقعی، و انیمیشن‌های Compose.

## ۷) دور چهارم — نشان، نوار کلای، دکمهٔ شبح، ورودی چاهی

پس از بازبینی «دقیقاً مثل سایت شد؟» و درخواست «UI را تا جایی که امکان دارد مثل سایت کن»، این موارد
که هنوز از سایت فاصله داشتند اصلاح شدند:

| مورد | سایت | اپ (قبل) | اپ (حالا) |
|---|---|---|---|
| نشان کنار نام | `BrandMark.jsx` = نشان + «حق‌سنج» + شعار برنجی ۱۰px | نشان + متن دست‌ساز با وزن Bold | `BrandLockup` با ساختار و رنگ‌های همان فایل (وزن Black، شعار `brass-300/90`) |
| اندازهٔ نشان | `w-8/w-10/w-12` (۳۲/۴۰/۴۸) | همیشه ۴۰dp (اندازهٔ فراخواننده بی‌اثر) | پارامتر `size` + `ContentScale.Fit` |
| نوار بالای چت | `.soft-clay-bar` (گرادیان + حاشیه + `inset 0 1.5px`) | سرفیس یک‌رنگ `Soft.card()` | `clayBarBrush()` + هایلایت ۱٫۵dp + `TopAppBar` شفاف |
| ورودی نوشتن | `.soft-well` + حلقهٔ فوکوس `brass-400/55` | `OutlinedTextField` کاملاً بی‌مرز روی سطح | چاه + حاشیهٔ `Soft.border()` + فوکوس `Brass400` + `SiteShape.Xxl` |
| دکمه‌های زیر پاسخ | شبح: بدون پس‌زمینه، متن برنجی، ۳۲dp | `TextButton` پیش‌فرض M3 (پدینگ بزرگ) | `GhostAction` (۱۵dp آیکون، `labelSmall`، گردی ۱۲dp) |
| آیکون لانچر | آیکون مربع‌گوشه با نشان زرین | قاب دوتایی زیر ماسک سیستم | گرادیان سرمه‌ای + نشان در ناحیهٔ ایمن (`docs/LOGO-FIXES.md`) |
| سهمیه در سایدبار | پلن + روز مانده + «X از Y پیام» + ماندهٔ گفتگو/پیام/سند | فقط نام پلن | همان سه ردیف، از پاسخ‌های سرور |

جزئیات نشان و آیکون: `docs/LOGO-FIXES.md` و پیش‌نمایش بصری `docs/brand-preview.html`.
جزئیات منطق گفتگو: `docs/CHAT-PARITY-SITE.md`.

شاهد این دور: `verify/typecheck.sh` → ok (۰ خطای نوع) · `verify/tokens.py` → ۳۹/۳۹ · `verify/run.sh` → pass=۲۶ fail=۰.
