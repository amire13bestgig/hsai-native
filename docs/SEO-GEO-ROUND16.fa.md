## ۲) اصلاحات انجام‌شده

### ۲٫۱ یک منبع حقیقت برای مسیرها
`scripts/seo.mjs` (تازه) تمام لایهٔ سئو را در خود دارد: عنوان/توضیح/pاسخ کوتاه/نکته‌ها/پیوندها **و** سازندهٔ `sitemap.xml`، `robots.txt`، `llms.txt`، `llms-full.txt`. `prerender-meta.mjs` فقط مسیرها را تعریف می‌کند؛ از همان فهرست، هر پنج خروجی ساخته می‌شود. نتیجه: سایتمپ دیگر نمی‌تواند از صفحات عقب بماند.

### ۲٫۲ پوشش: ۳۶ → ۱۵۵ صفحه
| نوع | تعداد | منبع انتخاب |
|---|---|---|
| صفحه‌های ثابت (خانه، قوانین، ماشین‌حساب، راهنماها، مهلت‌سنج، تعرفه، درباره، شرایط، حریم خصوصی، تماس، سوالات، API) | ۱۲ | دستی، با متن بازنویسی‌شده |
| راهنماهای گام‌به‌گام | ۱۰ | `src/data/seoGuides.js` (عنوان، خلاصه، مراحل، پرسش‌ها) |
| مواد قانونی با صفحهٔ اختصاصی | ۱۳۳ | **داده‌محور**: موادِ پراستناد در گفتگوهای واقعی + فهرست مواد پرتقاضا؛ سقف ۲۲ ماده از هر قانون برای توازن |
| صفحات خصوصی با `noindex, nofollow` | ۱۰ | `/app*`, `/auth/*`, `/payment/callback` |

### ۲٫۳ «پاسخ کوتاه» اول (answer-first) در هر صفحه
هر پوستهٔ پیش‌رندر با `<p id="hsai-answer">` شروع می‌شود: ۳۵ تا ۱۳۰ واژه که مستقیم به پرسش اصلی صفحه پاسخ می‌دهد (برای مواد قانونی: نقل متن رسمی + نقش آن + مسیر اقدام). سپس «نکته‌های کلیدی»، «مراحل کار» (راهنماها)، «پرسش‌های پرتکرار» و «صفحه‌های مرتبط». همین ساختار در `llms-full.txt` هم می‌آید.

### ۲٫۴ دادهٔ ساخت‌یافتهٔ متناسب با نوع صفحه
| نوع صفحه | موجودیت‌های JSON-LD |
|---|---|
| همه | `LegalService + Organization` (با `knowsAbout`، `contactPoint`، `areaServed: IR`)، `WebPage` + `speakable` |
| خانه | + `WebSite` با `SearchAction` (`/laws?q=`) |
| غیر خانه | + `BreadcrumbList` سه‌سطحی (خانه → قوانین → ماده) |
| مادهٔ قانون | + `Legislation` با `legislationIdentifier`، `text`، `dateModified` |
| راهنما | + `Article` + `HowTo` (مراحل، `totalTime`) + `FAQPage` + `author/reviewedBy` |
| ماشین‌حساب / مهلت‌سنج | + `WebApplication` (`applicationCategory: LegalService`، `isAccessibleForFree`) |
| تعرفه | + `Service` |
| سوالات متداول | + `FAQPage` ۶ پرسش |

### ۲٫۵ رفع تناقض موجودیت
تعریف `Organization` از `index.html` حذف شد و فقط در لایهٔ ساخت تزریق می‌شود (یک اعلام، یک `@id`، نام درست). نام تکراری `"حک‌سنج | حک‌سنج"` هم از بین رفت.

### ۲٫۶ فایل‌های ماشین‌خوان (GEO)
- `sitemap.xml`: ۱۴۵ آدرس **یکتا** (بدون آدرس پارامتری)، `lastmod` واقعی تاریخ ساخت، `priority`/`changefreq` بر اساس نوع صفحه.
- `robots.txt`: `Disallow` برای `/api/`, `/app`, `/auth`, `/payment` + مجازسازی صریح ۱۱ خزندهٔ AI (GPTBot, OAI-SearchBot, ChatGPT-User, PerplexityBot/User, ClaudeBot/Claude-SearchBot, Google-Extended, Applebot-Extended, Bingbot, CCBot) + خط `Sitemap`.
- `llms.txt` (۱۱ کیلوبایت): شناسهٔ موجودیت، واقعیت‌های قابل نقل، فهرست صفحات کلیدی، ۲۴ مادهٔ نخست، پاسخ کوتاه پرسش‌های پرتکرار، و **راهنمای استناد**.
- `llms-full.txt` (۳۰۵ کیلوبایت): متن کامل قابل استناد همهٔ ۱۴۵ صفحه (پاسخ کوتاه + نکته‌ها + مراحل + متن ماده + پرسش‌ها).
- حذف `public/sitemap.xml`، `public/robots.txt`، `public/llms.txt` (دیگر دستی نگه‌داری نمی‌شوند).

### ۲٫۷ دروازهٔ `verify/seo.py`
۳۵۲۱ بررسی روی خروجی واقعی `dist/`: طول و یکتایی عنوان/توضیح، `canonical` خودارجاع، `hreflang`، `og:*` (مطلق + وجود فایل تصویر)، `twitter:card`، `lang/dir`، `viewport`، یکتا بودن `h1`، وجود و طول «پاسخ کوتاه»، نوع‌های JSON-LD لازم برای هر نوع صفحه، `speakable`، سالم بودن پیوندهای داخلی پوسته، هم‌خوانی دقیق سایتمپ با صفحات ایندکس‌شدنی، صحت `lastmod`، نبود آدرس پارامتری/تکراری، بندهای `robots.txt`، و محتوای `llms.txt`/`llms-full.txt`. این دروازه اکنون مرحلهٔ ۲ از ۷ در `verify/run-all.sh` است.

## ۴) آنچه هنوز تأیید یا انجام نشده (صریح)

1. **اثر واقعی روی گوگل سنجیده نشده** — هیچ‌یک از این تغییرات مستقر نشده است؛ تا استقرار، `hsai.ir` همان نسخهٔ قدیمی را سرو می‌کند.
2. **ثبت در Search Console / Bing / IndexNow انجام نشد** — نیازمند دسترسی یا کد تأیید مالکیت.
3. **بدون دادهٔ ایندکس واقعی** نمی‌توان گفت کدام صفحات بیشترین تقاضا را دارند؛ انتخاب ۱۳۳ ماده بر پایهٔ استنادهای داخل سامانه بوده، نه جستجوی گوگل.
4. **بدون بازبینی حقوقی انسانی**: متن «پاسخ کوتاه» مواد قانونی نقل رسمی است، ولی «نکته‌های کلیدی» و راهنماها باید یک حقوق‌دان تأیید کند.
5. **تصویر OG مشترک**: همهٔ صفحات یک `og-cover.jpg` دارند؛ تصویر اختصاصی برای هر بخش ساخته نشد.
6. **`hp`/`Offer` بدون قیمت**: عدد تعرفه در ساخت‌یافته نیامد چون قیمت‌ها منبع ثابت در کد ندارند.

### د) دو نقص شناخته‌شدهٔ باقی‌مانده (صادقانه)

1. **URL ناشناختهٔ قانون → ۲۰۰ به‌جای ۴۰۴**: `/laws/civil-code/999999` پوستهٔ SPA را می‌گیرد. رفع کامل نیاز به Middleware لبه با کوئری DB دارد؛ فعلاً `canonical` و `noindex` مسیرهای موجود مانع ایندکس نادرست می‌شوند، اما «soft 404» در Search Console دیده خواهد شد.
2. **متغیرهای `BUNDLE_VERSION` / `BUNDLE_FALLBACK`** روی پروژه باقی مانده‌اند تا استقرار از بستهٔ سورس تکرارپذیر بماند. **به‌محض اتصال مخزن گیت باید حذف شوند** (بند ۱۲).

### ه) افزوده به فهرست نیازمندی‌ها

12. **اتصال مخزن گیت به پروژهٔ Vercel** (GitHub/GitLab) — تا هر push خودکار مستقر شود و `BUNDLE_*` حذف شود؛ الان مسیر استقرار، آپلود بستهٔ سورس با Connector است.
13. **دسترسی Search Console** برای ثبت سایتمپ و دیدن پوشش ایندکس (هنوز نداده‌اید؛ بدون آن، اثر سئو قابل سنجش نیست).
14. تأیید اینکه می‌خواهید **۴۰۴ واقعی** برای URLهای قانون ناموجود پیاده شود (نیاز به Middleware + کوئری DB؛ هزینهٔ عملکردی کوچک دارد).
