# آزمون زنده API و اصلاح منطق کلاینت بومی

## محدوده و مجوز

با اجازه کاربر، از مسیر عادی ورود و با همان حساب، API تولید `https://hsai.ir/api/v1` بررسی شد. ورود و تمدید نشست موفق بودند. ایجاد داده آزمایشی و مصرف سهمیه مجاز بود. هیچ رمز، پروفایل، تیکت، پرداخت، اشتراک یا داده قبلی کاربر تغییر داده نشد. مسیرهای مدیریتی استفاده نشدند. سایت و سرور تغییر نکردند؛ اصلاحات فقط در سورس بومی، تست‌ها و مستندات است. APK، AAB و ZIP جدید ساخته نشد.

اطلاعات ورود و توکن در سورس، fixtureها و گزارش تحویلی ذخیره نشده‌اند؛ فایل موقت نشست در پایان حذف شد.

## آزمون‌های زنده

| مسیر یا جریان | نتیجه واقعی |
|---|---|
| ورود و refresh | HTTP 200؛ توکن، کاربر و اشتراک برگشتند |
| `/me` و فهرست گفتگو، سند، تحلیل، مهلت، پرداخت و تیکت | پاسخ موفق و بررسی شکل داده؛ مقادیر شخصی وارد گزارش نشدند |
| قوانین، مجموعه‌ها، مقایسه‌ها، طرح‌ها و تنظیمات | پاسخ موفق؛ ساختار صفحه‌بندی و فهرست بررسی شد |
| هر ۱۰ محاسبه‌گر با نشست همین حساب | پاسخ موفق و بررسی مستقل حسابی روی خروجی‌ها |
| چت عادی | متن پاسخ، شناسه گفتگو و پیام، استنادها و وضعیت اشتراک برگشت |
| دریافت مجدد گفتگو | دو پیام اولیه با نقش و متن درست در پاسخ بودند |
| بازخورد روی پیام آزمایشی | موفق |
| ساده‌سازی همان پیام | موفق؛ کلید واقعی `simplified_content` است |
| چت جریانی | دریافت stage، delta و done؛ متن تجمیع delta دقیقاً با answer نهایی برابر بود و شناسه گفتگو یکسان ماند |
| ساخت سند | پس از اصلاح قرارداد موفق؛ پاسخ شامل `document` و `subscription` است |
| ویرایش و خواندن دوباره سند | متن ویرایش‌شده عیناً از سرور خوانده شد |
| دریافت Word سند آزمایشی | HTTP 200، محتوای دودویی ZIP معتبر و Content-Type مربوط به DOCX؛ باز شدن دستی در Word آزموده نشد |
| ثبت و تکمیل مهلت آزمایشی | HTTP 201 و سپس `updated: true` |
| تحلیل متن ساختگی | موفق؛ تفاوت رفتار kind و scan_mode مشخص شد؛ OCR تصویری اجرا نشد |

سه درخواست اولیه با قرارداد مستندشده، HTTP 400 گرفتند: ایجاد consultation بدون message، ساخت سند بدون subject و ایجاد مهلت بدون case_title. این شکست‌های تشخیصی پنهان نشده‌اند. برنامه بومی برای ایجاد گفتگو از `/chat` استفاده می‌کند؛ مسیر مستقل `/consultations` بدون متن، سازنده خالی گفتگو نیست.

## اشکالات پیدا شده و اصلاح در سورس

1. **گفتگوی قبلی بارگذاری نمی‌شد:** generation قبل از تغییر صفحه ذخیره می‌شد و navigate آن را عوض می‌کرد؛ در نتیجه پاسخ معتبر به‌اشتباه دور ریخته می‌شد. اکنون ابتدا مقصد مشخص و سپس نسل درخواست ثبت می‌شود. تست بازگشت متن واقعیِ mock به صفحه چت اضافه شد.
2. **ساخت سند با title/details خطا می‌داد:** سرور `subject` می‌خواهد. مهم‌تر اینکه حتی پس از رفع خطا، شرح ارسالی در `details` و در آزمون جداگانه `facts` به متن تولیدی راه پیدا نکرد. با عبارت ساختگی مشخص بررسی شد که قرار گرفتن شرح داخل `subject` آن را به خروجی می‌رساند. کلاینت اکنون عنوان و شرح/خواسته را در subject یکپارچه می‌کند و فیلدهای مستندشده را نیز نگه می‌دارد. عنوان نهایی ممکن است توسط سرور تولید یا کوتاه شود.
3. **ثبت مهلت خطا می‌داد:** `case_title` و `deadline_date` علاوه بر `title` و `due_date` ارسال می‌شوند. ثبت و PATCH با این قرارداد موفق بود.
4. **نوع تحلیل قرارداد رعایت نمی‌شد:** `kind=contract` به‌تنهایی باعث تحلیل پیش‌فرض ابلاغیه شد؛ سرور برای متن غیرقضایی حتی مهلت ۲۰ روزه نامرتبط پیشنهاد کرد. با `scan_mode=contract_risk`، خروجی واقعاً به تحلیل ریسک قرارداد تغییر کرد. برای ابلاغیه `sana_notice` صریح ارسال می‌شود.
5. **صحت محتوای AI:** سازگاری scan_mode ایراد نوع درخواست را رفع می‌کند، نه صحت حقوقی تمام خروجی‌ها را. هشدار روشن درباره احتمال اشتباه و لزوم تأیید مستقل هر مهلت به نمایش نتیجه اضافه شد؛ اپ بر اساس خروجی تحلیل یادآور خودکار نمی‌سازد. ایراد پیشنهاد مهلت نامرتبط مربوط به سرور/مدل است و با تغییر ظاهر ادعای رفع کامل آن نشده است.
6. **ساده‌سازی موفق ولی متن در اپ پیدا نمی‌شد:** پشتیبانی از `simplified_content` اضافه شد.
7. **از دست رفتن استناد در SSE:** ساخت مجدد پیام در هر delta، استنادهای رویداد قبلی را پاک می‌کرد. اکنون فقط متن همان پیام به‌روزرسانی می‌شود. اشتراک رویداد done نیز در state اعمال می‌شود. تست ترتیب articles → delta → delta → done اضافه شد؛ این ترتیب با mock آزمایش شد، چون جریان زنده این بار رویداد articles مستقل نداشت.
8. **صفحه‌بندی نادرست:** گفتگوها `pagination.total` دارند، اما بعضی فهرست‌ها کل مجموعه را می‌دهند و page/limit را نادیده می‌گیرند. وجود یک صفحه پر دیگر به‌تنهایی نشانه صفحه بعد نیست؛ کلاینت برای پاسخ صفحه‌بندی‌شده از total/limit و برای آرایه کامل از برش محلی استفاده می‌کند.
9. **شناسه استعلام تاریخچه پرداخت:** پاسخ فهرست از `authority_code` استفاده می‌کند؛ این نام به‌عنوان alias خوانده می‌شود. استعلام درگاه روی پرداخت‌های قبلی اجرا نشد.
10. **پاسخ دیررس روی صفحه دیگر:** نتیجه محاسبه یا تحلیل پس از جابه‌جایی دیگر نتیجه صفحه جدید را بازنویسی نمی‌کند؛ کنترل generation و تست regression اضافه شد.

## کنترل مستقل حسابی محاسبه‌گرها

این بررسی صحت محاسبات نسبت به ورودی‌ها و نرخ/فرمول اعلام‌شده سرور است، نه تأیید حقوقی مستقل قوانین یا نرخ‌های روز:

- دادرسی مطالبه ۱۵۰ میلیون: تمبر بدوی **۵٬۰۵۰٬۰۰۰** و با دفتر خدمات **۵٬۴۱۰٬۰۰۰ تومان**؛ محاسبه پلکانی مستقلاً تطبیق شد.
- مهریه ۱۱۰ سکه با قیمت ۱۰۰ میلیون: **۱۱ میلیارد تومان**؛ آزمون ۱۱۱ سکه سقف ۱۱۰ را حفظ کرد.
- دیرکرد: نسبت شاخص‌های برگشتی بدون استفاده از نسبت گرد‌شده محاسبه شد؛ خسارت **۱۰۸٬۵۰۴٬۹۳۰ تومان** و جمع با اصل بدهی تطبیق داشت.
- ارث: ماترک یک میلیارد، یک زوجه، یک پسر و یک دختر؛ سهم همسر **۱۲۵ میلیون**؛ جمع سهم‌ها یک میلیارد و نسبت سهم پسر به دختر تقریباً دو بود.
- کار: حقوق ماهانه ۱۲ میلیون برای ۱۲ ماه و بدون مرخصی/فرزند؛ سنوات + عیدی **۳۶ میلیون تومان**.
- وکیل برای خواسته ۱۵۰ میلیون: تعرفه پلکانی **۱۱ میلیون** و جمع سهم ۶۰٪ و ۴۰٪ برابر کل.
- دیه کامل فرضی ۱٫۶ میلیارد و آسیب ۱۰٪: **۱۶۰ میلیون**؛ ماه حرام برای آسیب عضو افزایش نداد و در فوت مبلغ **۲٬۱۳۳٬۳۳۳٬۳۳۳** برگشت.
- مالیات ارث نمونه سه دارایی: جمع ریز مالیات‌ها **۸۷ میلیون تومان**.
- اجرای حکم ۱۰۰ میلیون: **۵ میلیون** و با سازش **۲٫۵ میلیون تومان**.
- عایدی سرمایه نمونه با تعدیل تورم مرکب اعلام‌شده: سود تعدیل‌شده **۳۱۰ میلیون** و مالیات **۷۷٫۵ میلیون تومان**؛ فروش با زیان مالیات صفر داد.

هر شش آزمون مرزی زنده موفق بود. fixture خروجی‌های عمومی محاسبه‌گرها و تست حسابی مستقل در سورس تست نگهداری شده‌اند؛ داده حساب یا پاسخ‌های خصوصی AI در آن‌ها نیست.

## پاک‌سازی و آثار باقی‌مانده

- گفتگوی آزمایشی ۱۰۷، اسناد ۲۰ تا ۲۳ و مهلت ۶ حذف شدند؛ با خواندن مجدد فهرست‌ها، نبود تمام این شناسه‌ها تأیید شد. تعداد گفتگوها به ۷۴، اسناد به ۶ و مهلت‌ها به ۴ برگشت.
- **دو تحلیل آزمایشی با شناسه‌های ۸ و ۹ باقی مانده‌اند**؛ قرارداد رسمی مسیر DELETE برای scanner ندارد. برای حذف آن‌ها از مسیر غیرمجاز یا مدیریتی استفاده نشد.
- آزمون‌های AI از حساب و سهمیه آن استفاده کرده‌اند؛ شمارنده مصرف به عقب برگردانده نشده است.
- هیچ پرداخت یا تیکتی ساخته نشد؛ تغییر رمز، OTP/SMS، ویرایش پروفایل، OCR تصویر و پرداخت واقعی اجرا نشدند.

## آزمون نهایی سورس

**۷۱ تست موفق، صفر شکست/خطا/skipped** در اجرای نهایی با فعال بودن تست‌های اختیاری:

- ۳۲ تست پایه
- ۲۱ تست رابط و regression روی Robolectric
- ۱۳ تست سازگاری قرارداد واقعی
- ۲ تست خروجی حسابی محاسبه‌گرها
- ۲ تست زنده عمومی با ApiClient بومی
- ۱ تست زنده خواندن احراز هویت‌شده با همان ApiClient بومی و توکن موقت حساب

آزمون‌های نوشتن انتهابه‌انتها مستقیماً روی API با ابزار HTTP اجرا شدند؛ همه ۷۱ تست، آزمون زنده نوشتن نیستند. Lint بدون خطا و با شش هشدار نسخه جدیدتر وابستگی‌هاست. ساخت APK انجام نشد و تست گوشی واقعی همچنان جداگانه لازم است.

شواهد بدون اطلاعات ورود در `verification/api-audit/` قرار دارند.
