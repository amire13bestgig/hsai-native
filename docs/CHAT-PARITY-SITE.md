## ۱) کشف اصلی: اپ به «درِ دیگری» از همان ساختمان می‌زد

سایت گفتگو را از خانوادهٔ مسیرهای **`/api/chat/...`** می‌گیرد (`utils/api.js → '/api/chat/stream'`)،
ولی اپ از **`/api/v1/chat/stream`** استفاده می‌کرد. هر دو روی همان دیتابیس کار می‌کنند، ولی قرارداد و
رفتارشان یکی نیست:

| مورد | وب `/api/chat/stream` | اپ `/api/v1/chat/stream` (قبل) |
|---|---|---|
| کاربر **بدون اشتراک** | سهمیهٔ رایگان ماهانه مصرف می‌شود و **پاسخ می‌گیرد** | پیش از هر پاسخی `NO_SUBSCRIPTION` → **هیچ پاسخی** |
| رویداد سهمیه | `event: quota {free_quota}` | ندارد |
| مرحلهٔ آغازین | `stage` = «دریافت پیام و آغاز تحلیل حقوقی...» | ندارد |
| تاریخچه‌ای که به مدل می‌رود | `role, content, verification_json` (بافت راستی‌آزمایی) | `role, content` |
| بدنهٔ `done` | `conversation`, `is_new_conversation`, `user_message`, `assistant_message`, `subscription`, `free_quota` | `conversation_id`, `answer`, `cited_articles`, … |
| بازگشت سهمیه در خطا | `refundFreeMessage` | — |

یعنی مهم‌ترین تفاوت «منطق پاسخ‌دهی» این نبود که متن چطور ساخته می‌شود (آن کار سرور است و برای هر دو یکی است)،
بلکه این بود که **اپ گروهی از کاربران را اجازهٔ پرسیدن نمی‌داد** که سایت اجازه می‌داد.

### اصلاح
`ApiClient` حالا جویبار را از ریشهٔ وب می‌گیرد (`https://hsai.ir/api` + `/chat/stream`) و اگر آن مسیر روی
استقرار نبود (۴۰۴/۴۰۵/۵۰۱) **یک‌بار** به `/api/v1/chat/stream` برمی‌گردد:

```kotlin
fun stream(body: JSONObject): Flow<StreamEvent> = flow {
    try { emitAll(streamFrom(body, webBase, allowFallback = true)) }
    catch (e: ApiException) {
        if (e.code != LEGACY_ROUTE_MISSING) throw e
        emitAll(streamFrom(body, base, allowFallback = false))
    }
}
```

هر دو شکل `done` پشتیبانی می‌شود (`ApiContract.conversationId` + `chatMessage`)، پس هیچ‌کدام از دو
قرارداد پیش‌فرض گرفته نمی‌شود.

### آنچه **عمداً** یکسان نشد
- **پاسخ «یک‌جا» به‌جای جریانی**: در اپ باقی ماند فقط به‌عنوان مسیر پشتیبان آزمون (`streaming=false`)، نه گزینهٔ کاربر.
- **چاپ مرورگری (`window.print`)**: در اندروید معادل ندارد؛ همان کار با «دانلود Word» انجام می‌شود.
- **`is_new_conversation`**: اپ پس از پایان جریان فهرست گفتگوها را از سرور تازه می‌کند (`loadSidebar`)، پس نتیجه یکی است.
